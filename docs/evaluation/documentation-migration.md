[Up](README.md)

The [section ledger](migration-coverage.json) records 452 inspected headings,
classification, source digest and destination before retirement. Another 35
paragraph records map the mixed execution/evidence sequence individually. It is evidence,
not a navigation database or architecture authority.

## Composition and legacy depth

Architecture entries are recomposed into thirteen planes. The former large
compiler/runtime/C API material is divided by explanation versus exact ABI or
program contract. Exact contracts, ADR reasoning, baseline comparisons and
family observations intentionally retain lookup depth. Guides retain procedures.
Research separates current foundations from hypotheses, mechanisms and gates.

The complete capability matrix remains visible. Completed delivery exits use
optional disclosure; selected work and blockers do not. Memory survives only
as derived traps and re-entry routes. TEMP's bootstrap, empty registers and
superseded baseline remain in Git, with its unique research questions rescued.

## Publication qualification

Canonical sources drive the HTML reader and complete printable dossier. Native
markup was projected through the GitHub Markdown API for every canonical page;
this checks sanitization and hidden metadata without publishing candidate work.
Mermaid was additionally loaded in GitHub's actual viewer on a public blob page
with explicitly injected candidate content: seven source graphs, light/dark,
14 rendered views. This is candidate review, not inspection of a pushed new blob.

Browser review covers 26 major pages at 390, 768 and 1440 pixels, both themes,
in native-style and enhanced projections. It checks overflow, image loading,
page identity, metadata residue, keyboard figure controls, search, table filters
and mobile navigation. First and middle viewports were inspected for reading
rhythm. Complex diagrams retain static links and zoom for detailed inspection.
PDF uses Chromium with optional detail expanded and internal dossier links.

The review found and corrected stale C-options/local-protocol version prose,
an overwide deep compiler table, and overly dense Mermaid labels. No runtime
behavior was changed. Browser output and raw QA logs stay in ignored build or
disposable review directories, rather than acquiring documentation authority.

## Validation scope

- `make docs-check`: metadata, links/anchors, no orphans, controlled identities,
  all Task/capability counts, seven diagram projections, three observation projections
  and publication refusal tests.
- `make docs-site`: complete HTML reader and printable book from canonical sources.
- `make test-docs-surface check-qa-registry test-operator-registry`: affected executable
  entry assertions, QA registration and documentation-owner paths.
- `python3 tools/qa.py run structural --jobs 2`: source ownership/layout, ABI,
  architecture, docs, operator surfaces and no-NVCC build qualification.
- GitHub API/viewer and installed Chromium/Playwright: actual visual/render review;
  PDF inspection includes extracted text and sampled pages.
- `git diff --check`: patch hygiene.

Final run identities and exact result counts are reported in the milestone
closure. No model benchmark, GPU numerical campaign, upstream model evaluation
or release qualification is claimed by these documentation checks.
