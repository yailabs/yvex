# YVEX Re-entry Memory

**Derived traps worth remembering; canonical owners win conflicts.**

[Up](README.md)

> Derived context only. Follow the linked owner before acting on a reminder.

## Traps that cost a session

- **A completed finite-decision producer is not A03.** Resolve the exact selected
  identifier in [Tasks](TASKS.md); do not substitute the latest completed commit.
- **An old local binding can be malformed, not merely old.** Follow
  [artifact admission](../architecture/artifacts-admission.md); resealing or
  renaming bytes is not a migration strategy.
- **Mapped CUDA accessibility is not resident GPU memory.** Read the
  [resource model](../architecture/scheduling-resources.md) before adding byte classes.
- **A package, a component oracle and a release prove different things.**
  Use the [evidence ladder](../evaluation/README.md), especially when inheriting a green test log.
- **Source movement invalidates a supposedly exact performance run.**
  The [QA snapshot rule](../evaluation/qa.md) includes dirty/untracked source deltas.
- **The old research bootstrap was never executable authority.** Target E/L,
  automatic recipe search and distributed topology remain under [Research](../research/README.md).

## Re-enter with the smallest useful context

Start from the selected Task, its plane and its exact contract. Add a family
dossier or hardware lane only when the claim needs it. Do not replay historical
reconciliation work or read every target doctrine to fix a local bug.
