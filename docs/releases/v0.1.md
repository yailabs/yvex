# v0.1.0 Readiness Contract

**Versioned scope and evidence gates; no implicit capability promotion.**

[Up](README.md)

Authority: version-specific target, scope, required release path, and explicit
non-claims. This record owns version-specific gate detail; [Status](../project-control/STATUS.md)
owns overall capability posture.
[Release Doctrine](doctrine.md) owns the meaning of those gates.

## Target

v0.1.0 targets identity-bound DeepSeek-V4-Flash-DSpark text generation on
NVIDIA DGX Spark / GB10 CUDA from a complete YVEX-produced GGUF artifact.

| Fact | Required value |
| --- | --- |
| Model target | `deepseek4-v4-flash-dspark` |
| Source family | DeepSeek-V4-Flash-DSpark checkpoint in the DeepSeek V4 family |
| Product executables | `yvex` |
| Hosted process | one persistent foreground `yvex serve` host with an explicitly loaded DeepSeek engine generation |
| Application profile | bounded local `yvex.openai.compat.v3` |
| Local protocol | [Current private contract](../contracts/local-protocol.md), qualified with the release |
| Release backend | admitted GB10 CUDA profile, with exact physical variant selected only after evaluation and benchmark |

The external source location is operator configuration, not release identity.
The pinned source revision and architecture facts are recorded in the
[DeepSeek technical record](../model-families/deepseek-v4-flash.md).

## Required generation path

Release generation uses one exact chain:

```text
prompt text
-> admitted tokenizer and prompt template
-> exact prefix reuse and suffix prefill
-> family-correct Transformer, MoE, and persistent state
-> final norm and complete-vocabulary logits
-> target-only sampling or DSpark proposal plus complete-target verification
-> target-authored accepted-prefix commit
-> EOS/stop classification
-> incremental detokenized text
-> committed native and application streaming
```

The chain must use the same artifact, package binding, deployment
specialization, engine generation, session, CPU/CUDA owners, and operator path
qualified by the release. Fixture tokens, synthetic logits, selected
components, external engines, or trace output cannot substitute for it.

No physical variant is the release profile until the required evaluation and
benchmark owners accept it. The gate table below retains the current version-specific state.

## Required closure

v0.1.0 requires all gates defined by [Release Doctrine](doctrine.md), including:

- exact source, architecture, transformation, physical-policy, artifact, and
  runtime-binding identities;
- complete artifact integrity, materialization, runtime lifecycle, and cleanup;
- CPU/CUDA conformance and fail-closed behavior;
- repeated generation, cancellation, partial-progress, reset, and reuse proof;
- behavior and quality evaluation over the hosted path;
- reproducible full-model latency, throughput, memory, and reliability
  benchmark evidence;
- canonical package/operator validation and claim audit;
- clean versioned release record and tag.

## Explicit non-claims

The unreleased v0.1 line does not currently claim:

- a release-qualified DeepSeek artifact;
- model behavior or quality evaluation;
- a release-grade full-model benchmark;
- public/remote serving, authentication, TLS, or remote security;
- complete OpenAI API or another provider compatibility surface;
- global ready-sequence continuous batching, automatic resource-driven engine
  swap, distributed serving, or restart-persistent sessions;
- complete device residency or CUDA tokenizer execution; admitted CUDA
  sampling is an implementation fact, not release qualification;
- optimized DSpark execution or production load-aware confidence scheduling;
- release qualification of Qwen, MiniMax, Mamba2, or other families; their
  differing execution evidence does not expand the v0.1 release scope;
- release readiness.

Selected execution and delivery dependencies remain in [Tasks](../project-control/TASKS.md).

## v0.1 Release Path

v0.1 targets DeepSeek-V4-Flash-DSpark text on admitted GB10 CUDA through a
complete YVEX artifact, native host and bounded compatibility surface.
[The version record][release] owns required scope; [doctrine][doctrine] owns
gate semantics. Spectrum breadth must not silently expand this release.
Native Cognitive State is an independent substrate direction, **not a new v0.1
gate**. This release may use today's context-compatible model architecture.

| Release gate | State | Evidence owner | Blocking prerequisite | What completion proves |
| --- | --- | --- | --- | --- |
| Source/artifact reproducibility | PARTIAL | [Artifacts][artifacts]; [model release][model-release] | Final source/recipe/build and independent qualification; candidate publication exists | Shipped artifact is reproducible, not just available |
| Runtime functional correctness | PARTIAL | [Runtime QA][qa]; [v0.1][release] | All lifecycle/numerical obligations on final profile; product paths already execute | Exact release path executes and fails correctly |
| Performance optimization boundary | PARTIAL | [GB10 optimization][gb10] | Measured bottleneck-driven closure | Selected implementation is intentional and characterized |
| Model behavior evaluation | BLOCKED | [Evaluation gate][doctrine] | Optimization boundary | Quality, tokenizer, refusal and long-context behavior |
| Full-model benchmark | NOT MEASURED | [Benchmark gate][doctrine] | Evaluation | Latency, throughput, memory and reliability |
| Packaging/distribution | PARTIAL | [Model release][model-release]; [v0.1][release] | Final artifacts, operator/package validation and versioned delivery | Releasable package, not just publication tooling |
| Release qualification | BLOCKED | [Release doctrine][doctrine] | Every required gate and claim audit | v0.1 may be claimed |

Established artifact/runtime mechanisms and partial **release-wide gates** are
consistent: release gates require the final variant and full obligation set.
No current physical variant is already the release profile.

```text
model_behavior_evaluation_ready=0
full_model_release_benchmark_ready=0
release_qualification_ready=0
```
